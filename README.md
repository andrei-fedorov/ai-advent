# TooManyRules — день 21

Ассистент по правилам настольной игры Too Many Bones (Chip Theory Games).
Пока без RAG — модель отвечает из общих знаний, чтобы наглядно сравнить с
версией, которая читает реальные правила. Неделя 5 (RAG) началась с дня 21:
индекс правил уже строится, ответы по нему — следующие дни.

День 21 открывает неделю 5 — **RAG** — с первого шага: **индекса правил**.
Русская книга правил базовой игры и два справочных листа («Навыки злодеев и
условия встреч», «Путеводитель гирлока») превращаются в локальный индекс:
текст из PDF → очистка по правилам документа → куски двумя стратегиями
(фиксированный размер и по структуре — разделы книги, записи глоссария) →
эмбеддинги локальной многоязычной моделью → SQLite, где у каждого куска
источник, раздел, страницы и язык. Индекс строит отдельная программа из
терминала (`./run.sh index`); приложение и агент в этот день не меняются, и
ассистент индексом пока не пользуется. Сравнение стратегий нарезки — в
[`docs/TooManyRules — День 21 сравнение нарезки.md`](docs/TooManyRules%20—%20День%2021%20сравнение%20нарезки.md).
Подробности — в разделе [«Индекс правил» ниже](#индекс-правил-день-21).

## Индекс правил (день 21)

Первый шаг RAG: правила из PDF — в локальный индекс с эмбеддингами и
метаданными у каждого куска. Строит его отдельная программа
`src/rag_index.py`; приложение индекс пока не читает, агент им не
пользуется — поиск и ответы по правилам появятся в следующие дни.

### Документы

| Документ         | Файл в `rag_sources/`                 | Что внутри                                      |
| ---------------- | ------------------------------------- | ----------------------------------------------- |
| `rules`          | `Правила игры v2.2.pdf`               | русская книга правил базовой игры, 32 страницы  |
| `villain-skills` | `Навыки злодеев и условия встреч.pdf` | глоссарий «Название — действие», 2 страницы     |
| `gearloc-guide`  | `Путеводитель гирлока.pdf`            | справка, на которую ссылается книга, 2 страницы |

Около 16 тыс. слов. PDF — материалы издателя: в git их нет (`rag_sources/` в
`.gitignore`), положите файлы в `rag_sources/` в корне репозитория. Сейчас
индексируются только русские документы; язык — поле описания документа
(`lang`), и английские правила добавятся строками в `presets.RAG_DOCUMENTS` и
пересборкой, без правки кода. FAQ издателя в индекс не идёт — он остаётся
MCP-сервером дней 17-20.

### Сборка

```bash
./run.sh index
```

1. **Извлечение** — PyMuPDF отдаёт строки с номером страницы, шрифтом и
   кеглем.
2. **Очистка** — по правилам документа из `presets.py`: мелкий кегль
   (надписи на картинках), страницы оглавления, состава и указателя, номера
   страниц, одинокие маркеры, управляющие символы долой; строки → абзацы,
   заголовки и записи глоссария помечены. Сколько выброшено по каждому
   правилу — в логе. Порядок блоков на страницах, где PyMuPDF путает
   колонки, — по колонкам.
3. **Нарезка** одной и той же очищенной копии двумя стратегиями:
   - `fixed` — окна по 1000 символов с перекрытием 150, граница — у ближайшего
     пробела; `section` — раздел, где кусок начался, `sections_spanned` —
     сколько разделов задел;
   - `structural` — раздел книги и путеводителя (по заголовкам) или запись
     глоссария; раздел длиннее 1600 символов делится по абзацам и
     предложениям на части «2/3».
4. **Эмбеддинги** — `intfloat/multilingual-e5-base` локально (768
   измерений, до 512 токенов на кусок; префиксы `passage:`/`query:` ставит
   `embedder.py`). Длина каждого куска меряется токенизатором модели: куски
   сверх 512 токенов модель молча обрезала бы, их число — в логе и отчёте.
5. **Запись** — `src/data/rag/index.sqlite3` (вне git): документы, куски со
   всеми метаданными (`chunk_id`, источник, заголовок документа, раздел,
   часть, страницы, язык, издатель/игра/издание, токены) и векторы `float32`.
   Собирается во временный файл одной транзакцией и ставится на место —
   прерванная сборка прежний индекс не портит; чужой файл по этому пути не
   затирается.
6. **Отчёт** — таблица сравнения стратегий в терминале: только числа (длины,
   оборванные предложения, разрезанные разделы и записи, время). Выводы — в
   [документе сравнения](docs/TooManyRules%20—%20День%2021%20сравнение%20нарезки.md).

**Первый запуск скачивает модель** (≈1,1 ГБ, в кэш Hugging Face
`~/.cache/huggingface`) — пара минут, один раз; дальше сборка идёт без сети
за ≈10 секунд. Ключ DeepSeek индексу не нужен: LLM он не вызывает.
Зависимости индекса (`pymupdf`, `sentence-transformers` и с ним `torch`) —
сотни мегабайт при первой установке. Лицензия PyMuPDF — AGPL: для учебного
проекта годится, для закрытого продукта его заменяют (например, `pypdf`).

### Другие режимы

```bash
./run.sh index --probe
```

Пробные вопросы из `presets.RAG_PROBE_QUESTIONS` по готовому индексу: три
ближайших куска каждой стратегии (близость, `chunk_id`, раздел, страницы,
начало текста) — только среди кусков языка вопроса. Без LLM, порогов и сборки
ответа: это проверка индекса, а не RAG.

```bash
./run.sh index --dump /tmp/tmr-dump
```

Сборка плюс выгрузка для глаз: `<doc>.<lang>.clean.txt` — очищенный текст
(заголовки с `## `, страницы строкой `--- стр. N ---`) и
`<doc>.<lang>.dropped.txt` — выброшенное по правилам. По ней подстраиваются
правила очистки.

`--db <путь>` — другой файл индекса (свой экземпляр, эксперименты: индекс в
`src/data/rag/` не трогается), `--sources <каталог>` — другой каталог PDF.
Относительные пути считаются от `src/` (туда переходит `run.sh`).

## Запуск ассистента

```bash
./run.sh
```

Скрипт сам создаёт `src/.venv` (если его ещё нет), ставит зависимости и
запускает `src/app.py` на http://127.0.0.1:7860

Перед первым запуском нужно один раз положить API-ключ в `src/.env` — см.
шаг 2 ниже; без него приложение запустится, но на первый же вопрос ответит
понятной ошибкой вместо ответа модели.

Необязательно (день 16): для блока MCP нужен собранный бинарник bgg-mcp в
`~/.local/bin/bgg-mcp` (сборка — в спецификации дня 16). Без него
приложение работает, а кнопка MCP покажет сбой стадии «запуск».

Свой сервер FAQ (день 17) собирать не нужно — он запускается тем же Python из
`src/.venv`; нужен доступ к сайту издателя. Без сети приложение работает, а
ходы с инструментами показывают ошибку инструмента «сайт FAQ недоступен».

Сервер FAQ издателя (`src/faq_watch.py`, дни 18-20) с дня 20 поднимает само
приложение, если его порт молчит, — строки `[FAQ-сторож]` идут в терминал
приложения, а при выходе приложение его останавливает. Можно запустить и
вручную, в своём терминале, — такой сервер приложение использует как есть и
не останавливает:

```bash
./run.sh faq-watch
```

Вики и файлы (день 20) запускаются тем же Python из `src/.venv` на каждый
вызов; вики нужен доступ к `boardgamehub.ru`. Если сервер недоступен, агент
получает инструменты остальных, а сбой — предупреждением в каталоге хода.
Подробности — в спецификации дня 20.

Индекс правил (день 21) строится отдельно и приложению не нужен: PDF в
`rag_sources/`, затем `./run.sh index` (первый запуск скачивает модель
эмбеддингов, ≈1,1 ГБ). `requirements.txt` с дня 21 тянет ещё `pymupdf` и
`sentence-transformers` с `torch` — первая установка дольше. Подробности — в
разделе [«Индекс правил»](#индекс-правил-день-21).

### Запуск ассистента пошагово вручную

Все команды выполняются из папки `src/` — код и виртуальное окружение
находятся там, а не в корне репозитория.

1. Перейти в `src/` и установить зависимости (Python 3.12+, проверено на 3.14):
   
   ```bash
   cd src
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```
   
   Если системный Python старый, свежий ставится одной командой через [uv](https://docs.astral.sh/uv/):
   `uv python install 3.14 --default`.

2. Получить API-ключ DeepSeek на https://platform.deepseek.com
   и положить его в файл `.env` внутри `src/`:
   
   ```bash
   echo 'DEEPSEEK_API_KEY=...' > .env
   ```
   
   `.env` не коммитится в репозиторий (см. `src/.gitignore`).

3. Запустить (из папки `src/`, с активированным `.venv`):
   
   ```bash
   python app.py
   ```
   
   и открыть в браузере http://127.0.0.1:7860

и таблицы цен между ним и `agent.py`/`presets.py` оставлено намеренно.

Стратегия подключена к агенту третьей зависимостью после конфига и хранилища
и, как хранилище, необязательна: без неё агент ведёт себя ровно как на дне 8.
Она — **состояние агента, а не поле `AgentConfig`**: конфиг заморожен и
описывает вызов модели, а стратегию переключают на живом агенте, не теряя
диалог. Протокол `ContextStrategy` объявлен в самом `context.py` (в отличие от
`HistoryStore`), потому что стратегия обменивается с агентом своими типами —
`ContextTask` и `StrategyState`; иначе `context.py` пришлось бы импортировать
`agent.py` и лист графа перестал бы быть листом.

Хранилище подключено к агенту через протокол `HistoryStore` (`load`/`save` по
`session_id`), объявленный в `agent.py` ещё на дне 6: день 7 подставил в эту
точку реализацию, не меняя публичный контракт агента. Туда же встанет SQLite,
когда появится VPS и несколько пользователей.

**Checkpoint и ветка (день 10)** — операция над самой историей, а не
стратегия и не зависимость агента: `Agent.save_checkpoint()` и `Agent.fork()`
работают со стеком сообщений и реестром напрямую. Ветка собирается через
параметр `seed` конструктора — тем же кодом (`_normalize_messages()`,
`_load_context()`), которым агент читает файл сессии, — чтобы в реестр не
попал недособранный агент (правило дня 6: регистрация последним шагом
конструктора). `branch_family()`/`branch_parent()` в `agent.py` вычисляют
семейство веток по происхождению агентов в реестре, а не по ссылкам,
хранимым у родителя.
