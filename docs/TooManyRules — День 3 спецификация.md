# TooManyRules — спецификация дня 3

Тема: Разные способы рассуждения

Эта спецификация — техническое задание для AI\-ассистента, который будет писать код.

## 1\. Задание челленджа (день 3)

Текст задания — платный контент челленджа, поэтому здесь не копируется. См. локально (не в git\-репозитории): `tasks/AI Advent Challenge_03.txt`.

## 2\. Что делаем конкретно для TooManyRules

Берём одну **действительно неоднозначную ситуацию по правилам** — не простой факт, а вопрос, требующий разбора нескольких взаимодействующих правил (это и есть «аналитическая задача» в терминах задания). Пример задачи (можно и нужно заменить на реальный спорный момент из своих партий — тогда сравнение будет полезнее, поскольку у тебя есть физическая книга правил, чтобы проверить, какой способ ответил точнее):

```
Бадди с Толстая кожа 2. Если Тинк бросает 1 атаку а потом бот бьет на два
Сколько урона пройдет по бадди?
```

Этот же вопрос прогоняется через API четырьмя способами:

**Способ 1 — прямой ответ.** Системный промпт из дня 1, без дополнительных инструкций про рассуждение, просто вопрос как есть.

**Способ 2 — «решай пошагово».** Тот же вопрос плюс инструкция в промпте: «Прежде чем дать финальный ответ, распиши рассуждение по шагам: какие правила применимы, в каком порядке они действуют, какие есть неоднозначности».

**Способ 3 — модель сама формулирует промпт.** Два вызова API подряд:

1. Просим модель: «Сформулируй идеальный промпт, который стоит использовать, чтобы точно разобрать этот вопрос по правилам Too Many Bones: \[вопрос\]». Получаем сгенерированный промпт.
2. Отправляем этот сгенерированный промпт отдельным запросом и получаем финальный ответ.

**Способ 4 — консилиум экспертов.** Один системный промпт описывает трёх персон, отвечающих последовательно или в одном ответе:

- **Rules Lawyer** — формально разбирает текст правил и порядок разрешения эффектов.
- **Game Designer** — рассуждает с точки зрения замысла/баланса игры, что скорее всего имелось в виду.
- **Skeptic** — ищет противоречия и слабые места в мнениях первых двух, указывает, где ответ неоднозначен.
  Финальный вывод — по возможности согласованная позиция или явное указание, в чём эксперты расходятся.

## 3\. Системные промпты (черновики)

Базовая ролевая часть промпта — как в дне 1 (роль TooManyRules) — используется во всех четырёх способах как основа, к ней добавляется:

**Способ 2:**

```
Прежде чем дать финальный ответ, распиши рассуждение по шагам:
1. Какие правила потенциально применимы к ситуации.
2. В каком порядке они должны разрешаться.
3. Есть ли в правилах прямое указание на этот случай или это интерпретация.
После рассуждения дай чёткий финальный ответ отдельным абзацем.
```

**Способ 3, шаг 1 (генерация промпта):**

```
Ты помогаешь сформулировать идеальный запрос к ассистенту по правилам
Too Many Bones для точного разбора следующей ситуации: «{вопрос}».
Составь промпт, который стоит использовать, чтобы получить максимально
точный и обоснованный ответ. Выведи только текст промпта, без пояснений.
```

**Способ 4:**

```
Разбери следующий вопрос по правилам Too Many Bones тремя голосами
последовательно:

1. Rules Lawyer — формально, опираясь только на текст правил и порядок
   разрешения эффектов.
2. Game Designer — исходя из вероятного замысла и баланса игры.
3. Skeptic — укажи, в чём первые два мнения расходятся или где ответ
   неоднозначен, и есть ли основания сомневаться в каждом из них.

В конце дай итоговый вывод: согласованный ответ или явное указание,
что вопрос требует уточнения у официального FAQ.
```

## 4\. Технические требования

- Тот же стек: Python, DeepSeek API.
- Реализация — отдельный скрипт (например, `day3_reasoning_methods.py`), который последовательно делает 4 (для способа 3 — 5, включая генерацию промпта) запроса к API и выводит все четыре финальных ответа друг за другом с подписанным способом.
- Основной чат\-продукт (`app.py`) из дня 1 трогать не обязательно.
- API\-ключ — как и раньше, только через `.env`, не коммитить.

## 5\. Что должно быть видно в видео (день 3)

1. Запуск скрипта дня 3.
2. Все четыре ответа на один и тот же вопрос, чётко подписанные (способ 1 / способ 2 / способ 3 / способ 4).
3. Устный или текстовый комментарий: отличаются ли ответы по содержанию, какой способ показался наиболее точным и обоснованным — здесь стоит сверить хотя бы один ответ с физической книгой правил Too Many Bones, раз RAG ещё не подключён, и явно сказать в видео, какой вариант оказался ближе к реальным правилам.

## 6\. Критерии приёмки

- Использован один и тот же вопрос (аналитическая задача с неоднозначностью) во всех четырёх способах.
- Все четыре способа реализованы отдельно и дают разные по форме (а возможно, и по содержанию) ответы.
- В выводе / видео явно сопоставлены результаты и указано, какой способ показался точнее, с кратким обоснованием.

## 7\. Что сознательно НЕ делаем на этом шаге

- RAG / реальную базу правил — неделя 5 (поэтому итоговая точность каждого способа оценивается вручную, по своей книге правил, а не автоматически).
- Управление форматом ответа (JSON, стоп\-последовательности) — это уже сделано в дне 2, здесь не обязательно, если не мешает читаемости сравнения.
- Память между запросами/сессиями — недели 2\-3.

Не расширяй объём задания сверх сравнения четырёх способов рассуждения на одной и той же задаче.
