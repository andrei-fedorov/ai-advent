# TooManyRules — спецификация дня 17

Тема: Первый инструмент MCP — свой MCP-сервер вокруг FAQ издателя Too Many Bones (два инструмента: список вопросов и текст статьи), подключённый к агенту через function calling DeepSeek; агент сам решает, когда сверяться с FAQ, вызывает инструменты и отвечает по их результату

## 1. Задание челленджа (день 17)

Текст задания — платный контент челленджа, поэтому здесь не копируется. См. локально (не в git-репозитории): `tasks/AI Advent Challenge_17.txt`. Комментариев организатора к дню 17 на момент написания нет.

Ключевое из задания: **реализовать свой MCP-сервер** вокруг любого API (подойдёт и mock API): **зарегистрировать инструмент, описать его входные параметры, вернуть результат**. Затем **подключить инструмент к своему агенту**: вызвать его из приложения, получить результат и использовать его. Результат — агент вызывает MCP-инструмент и получает результат; формат сдачи — **видео + код**.

Формат — «видео + код» без «/ текст», а результат — сам код. Поэтому **отдельного документа проверки у дня нет** (правило дней 12 и 16): проверка показывается в видео (§12), факты реального прогона записываются комментарием в коде (§7.4).

День 17 — второй день недели 4 («MCP»). На дне 16 приложение подключилось к чужому серверу (bgg-mcp) и получило список его инструментов; агент о MCP не знал. Сегодня сервер свой, а агент впервые им пользуется. Правила прошлых дней в силе и здесь не повторяются:

- **внешний мир — за своим модулем**: LLM API вызывается только в `agent.py`, диск трогает только `storage.py`, **клиентскую часть SDK `mcp` импортирует только `mcp_client.py`**. Сегодня к этому списку добавляется сервер, но он **отдельная программа**, а не модуль приложения (§3.1);
- **всё «про настолки» — в `presets.py`**: какую категорию FAQ читать и как запускать сервер, решает `presets.py`; ни сервер, ни `mcp_client.py`, ни агент про Too Many Bones не знают;
- **агент не знает ни про Gradio, ни про MCP**: инструменты приходят к нему необязательной зависимостью через протокол, как хранилища и модель памяти (§5.1);
- **переключатель меняет запрос, а не работу** (правило дней 9-15);
- **на экране — текущий день, прошлые свёрнуты** (правило аккордеонов);
- **абстракций под будущие дни не пишем**: один сервер, два инструмента, одно соединение на один вызов.

Все числа времени и токенов в примерах ниже — **условные, для иллюстрации формата**. Настоящие берутся из прогона (§7.4).

## 2. Что делаем конкретно для TooManyRules

Источник — **официальный FAQ издателя по Too Many Bones** на портале поддержки Chip Theory Games: `https://support.chiptheorygames.com/support/solutions/33000133540`. Это разъяснения издателя как раз по тем местам, где модель ошибается чаще всего: порядок эффектов начала хода, Poison, Engulf и Break, боты Tink, Picket, отдельные столкновения и лут. У публичного портала нет открытого API (API Freshdesk требует ключ агента поддержки), поэтому сервер работает со страницами сайта — тем же HTTP GET, что и браузер. Задание разрешает «любой API», и это API в широком смысле: у страниц стабильные адреса и разметка.

Картина недели складывается так: день 16 — чужой сервер BGG (мнения игроков, пока только каталог), день 17 — свой сервер FAQ (официальные ответы издателя), которым агент пользуется. С планом недели 5 это не конфликтует: там RAG по книге правил, а FAQ — отдельный источник. Базовую линию «без инструментов» для недели 5 даёт переключатель (§8.2).

Семь пунктов дня:

1. **`src/faq_server.py`** — новый MCP-сервер на официальном Python SDK v2 (`MCPServer`), транспорт stdio. Два инструмента: `faq_questions` (список вопросов FAQ) и `faq_article` (текст статьи). Сервер — отдельная программа: приложение запускает его процессом, а не импортирует (§3).
2. **`src/mcp_client.py`** — вызов инструмента `call_tool()` (одно полное подключение на один вызов, как `list_tools()` дня 16) и адаптер `McpToolBox`, через который агент получает каталог и вызывает инструменты (§4).
3. **`src/agent.py`** — function calling. Новая необязательная зависимость `tools` (протокол `ToolBox`), переключатель «Инструменты MCP в запросе», цикл раундов «модель → вызовы инструментов → модель» внутри `ask()`, журнал вызовов в ответе и журнале ходов (§5).
4. **`src/tokens.py`** — корзина `tools` в `RequestTokens`: схемы инструментов уходят в каждый запрос хода и стоят токенов (§6).
5. **`src/presets.py`** — описание сервера `FAQ_MCP`, лимиты цикла, сценарий проверки дня и замер (§7).
6. **`src/app.py`** — переключатель, блок «MCP: свой сервер FAQ (день 17)» наверху дебаг-панели (каталог инструментов и вызовы последнего хода), сценарий дня, перекладка аккордеонов (§8).
7. **`src/requirements.txt`, `README.md`** — явная зависимость `httpx` и раздел про свой сервер (§10).

Продуктовый смысл. На вопрос о правилах ассистент сначала сверяется с FAQ издателя: смотрит список вопросов, открывает подходящую статью, пересказывает ответ по-русски и даёт ссылку. Если в FAQ ответа нет, он так и говорит и отвечает из общих знаний, как раньше. Это первый случай в проекте, когда ответ опирается не только на то, что модель «помнит».

### 2.1. Источник: портал поддержки на Freshdesk

Что видно на сайте (проверено 22.09.2026, §2.9):

| Что | Значение |
| --- | --- |
| Корень FAQ | `/support/solutions` — 10 категорий: General, Crowdfunding, Order/Shipping, Cloudspire, burncycle, 20 Strong, **Too Many Bones**, Hoplomachus, The Elder Scrolls, Wroth |
| Категория Too Many Bones | `/support/solutions/33000133540`, заголовок `h2.solution-category-heading` — «Too Many Bones» |
| Разделы (папки) | 24: Battle, Baddie Skills and Encounter Terms, Tyrants, Specific Encounters, Loot, три дополнения, по разделу на героя, General Questions |
| Вопросов | 82 |
| Страница категории | по каждому разделу — название, число статей (`span.item-count`) и **не больше 5 статей**; у разделов, где статей больше, — ссылка «See all N articles» |
| Страница раздела | `/support/solutions/folders/<id>` — **по 10 статей на страницу**, дальше `…/page/2`, ссылка «Next» в `li.next` |
| Статья | `/support/solutions/articles/<id>` (часть адреса после номера необязательна): вопрос — `h2`, ответ — `article#article-body`, хлебные крошки — ссылки на категорию и раздел |
| Отдача | статический HTML без JavaScript и без защиты от ботов, ответ 200 примерно за 1-1,5 с |
| robots.txt | закрыт `/support/search` (и тикеты, вход); категории, разделы и статьи открыты |

**Стартовая точка — id категории, а не корень FAQ.** У издателя есть ещё одна игра с Too Many Bones в названии — 20 Strong. В её категории лежит **папка** «Too Many Bones» (одна статья, «"Face Up" Enemies — Scouted») — это правило колоды Too Many Bones для 20 Strong, а не для нашей игры. «General» тоже есть в обеих категориях. Если бы сервер шёл от корня и собирал всё, где упоминается «Too Many Bones», эта статья попала бы в выдачу, и ассистент выдал бы её за официальный ответ по нашей игре. От категории `33000133540` в FAQ 20 Strong не попасть. Числовой id в Freshdesk — стабильный ключ: категорию могут переименовать, а id останется.

Ещё две проверки делают выбор категории явным (§3.5):

- **имя категории сверяется**: сервер получает ожидаемое имя («Too Many Bones») и при несовпадении с заголовком страницы отвечает ошибкой, а не читает молча чужой FAQ;
- **статья проверяется по хлебным крошкам**: `faq_article` отдаёт только статью, у которой в крошках ссылка на нашу категорию. Номер статьи 20 Strong (например, `33000285781`) — ошибка инструмента, а не текст.

**Поиск сайта не используем**: `/support/search` закрыт в robots.txt. Искать по списку вопросов будет сама модель (§2.2): заголовки статей и есть вопросы («Can Patches heal one of Tink's bots?»).

### 2.2. Инструменты сервера

| Инструмент | Параметры | Что возвращает | Запросов к сайту |
| --- | --- | --- | --- |
| `faq_questions` | `section`: string, необязательный, по умолчанию `""` — фильтр по части английского названия раздела, без учёта регистра | список вопросов строками «номер · раздел · вопрос» в порядке сайта; при фильтре, под который не подошёл ни один раздел, — перечень разделов | 1 + разделы, где статей больше 5, со всеми страницами (сейчас 7) |
| `faq_article` | `article_id`: integer, обязательный — номер статьи из `faq_questions` | вопрос, раздел, ссылку и ответ издателя текстом | 1 |

Почему два инструмента, а не поиск:

- **Поиск по словам на нашей стороне не нужен.** Игрок спрашивает по-русски, FAQ — английский. Найти в списке из 82 вопросов подходящий по смыслу модель умеет лучше любого совпадения по словам, а список стоит ≈2-3 тыс. токенов (8,5 тыс. символов на прототипе).
- **Цепочка из двух вызовов видна в видео**: модель сама получает список, выбирает номер и открывает статью.
- **Раздел — удобный фильтр**: у каждого героя свой раздел, и вопрос «может ли Patches…» закрывается списком из двух строк.

Задание просит «описание входных параметров» — у каждого параметра есть описание в JSON Schema (`Field(description=…)`), и оно видно в каталоге инструментов в панели (§8.3).

### 2.3. Как агент пользуется инструментами: раунды одного хода

```
ask("Может ли Patches лечить ботов Тинка?")
  служебные работы дня 9-15 — как раньше (стратегия, страж, разбор памяти, роутер, трекер)
  каталог      mcp_client.list_tools(FAQ_MCP)            → faq_questions, faq_article   (новый процесс)
  раунд 1      модель: сообщения + tools=[2 схемы]       ← finish_reason=tool_calls: faq_questions(section="Patches")
               mcp_client.call_tool(...)                 → 2 строки                     (новый процесс)
  раунд 2      модель: + assistant(tool_calls) + tool    ← finish_reason=tool_calls: faq_article(article_id=33000210180)
               mcp_client.call_tool(...)                 → вопрос, ссылка, ответ         (новый процесс)
  раунд 3      модель: + assistant(tool_calls) + tool    ← finish_reason=stop: «Нет — Patches лечит только Gearloc'ов… (ссылка)»
  в историю    user: вопрос · assistant: текст раунда 3
```

- **Раунд** — один запрос к модели. Первый раунд — обычный основной запрос хода плюс параметр `tools`. Если модель ответила вызовами инструментов, приложение выполняет их и отправляет следующий раунд: те же сообщения плюс ответ модели с `tool_calls` и по сообщению `role: "tool"` на каждый вызов. Ход заканчивается, когда модель ответила текстом (`finish_reason` не `tool_calls`).
- **Решает модель**: вызывать ли инструмент, какой и с какими аргументами. Код не угадывает «вопрос про правила» и не вызывает инструменты сам.
- **В историю идут только вопрос и финальный ответ.** Промежуточные сообщения живут в пределах хода (§5.6).
- **Потолок раундов** — `TOOL_MAX_ROUNDS` (§7.2). Если модель на последнем разрешённом раунде снова просит инструмент, приложение делает ещё один, финальный запрос с `tool_choice="none"`: модель отвечает тем, что уже собрала (§5.5).

### 2.4. Соединение: одно на вызов

Каждое обращение к серверу — новый процесс и новое соединение, как кнопка дня 16: запуск → согласование → `tools/list` или `tools/call` → закрытие. Между вызовами ничего не хранится: ни процесса, ни каталога, ни страниц сайта. Поэтому в ходе с двумя вызовами сервер запускается три раза (каталог плюс два вызова).

Цена — время. По прототипу: запуск Python-процесса с SDK — ≈0,4 с, `faq_questions` — ≈4 с (7 страниц, параллельно не больше 4), `faq_article` — ≈1,7 с. Ход с двумя вызовами дольше обычного на ≈7 с плюс два лишних раунда модели. Для учебного дня это приемлемо, а цену должно быть видно в панели и журнале ходов (§8.3). Долгоживущее соединение и кэш — решение следующих дней (§14).

### 2.5. Две эры протокола — теперь с другой стороны

bgg-mcp дня 16 — сервер старой эры: проба `server/discover` не принималась, соединение шло рукопожатием `initialize` на протоколе 2025-06-18. Свой сервер на SDK v2 понимает эру 2026-07-28: тот же `Client` в режиме по умолчанию договаривается с ним **через `server/discover`, без рукопожатия** (проверено на прототипе, §2.9). Клиент дня 16 при этом не меняется — в этом смысл того, что `mode` не закрепляли. В панели обе строки стоят рядом: у BGG «проба не принята — рукопожатие initialize», у FAQ «server/discover, без рукопожатия».

### 2.6. Function calling у DeepSeek

OpenAI-совместимый формат, которым проект уже пользуется через SDK `openai`:

| Что | Как |
| --- | --- |
| схема инструмента | `{"type": "function", "function": {"name", "description", "parameters"}}`; `parameters` — `inputSchema` из `tools/list` как есть |
| ответ с вызовами | `finish_reason == "tool_calls"`, `message.tool_calls[i]`: `id`, `function.name`, `function.arguments` — **строка** JSON |
| результат | сообщение `{"role": "tool", "tool_call_id": id, "content": текст}` — **на каждый** `tool_call` раунда, до следующего запроса |
| запрет вызова | `tool_choice="none"` — модель отвечает текстом (проверено на обеих моделях) |
| несколько вызовов в раунде | допустимы; выполняются по порядку, ответы идут в том же порядке |

**Режим thinking (пресет «Флагман + thinking»).** Документация DeepSeek требует: если в запросе есть `tools`, то `reasoning_content` **всех прошлых ходов** нужно передавать обратно, иначе API ответит 400. История проекта рассуждений не хранит (дни 5-6: «API не принимает рассуждение обратно в контекст» — для запросов без `tools` это верно и сейчас). Проверено 22.09.2026 (§2.9): `deepseek-v4-pro` с thinking **принимает** и историю без `reasoning_content`, и раунд, где у сообщения с `tool_calls` его нет. Решение дня:

- **внутри хода** сообщение модели с `tool_calls` уходит в следующий раунд вместе с её `reasoning_content`, если он есть, — по документации: объект уже под рукой, и это ничего не стоит;
- **между ходами** история остаётся как есть — только текст. Хранить рассуждения в истории — это новый формат файла сессии и заметная цена. Если API однажды начнёт отвечать 400 на пресете с thinking, причина известна заранее: она записана здесь и в комментарии у цикла (§5.5). Ошибка при этом приходит обычным путём — как `AgentReply(ok=False)`, со стеком без изменений.

### 2.7. Где лежит и сколько живёт

**Ничего нового на диск не едет.** Формат файла сессии не меняется.

| Что | Где живёт | Переживает |
| --- | --- | --- |
| описание сервера, id и имя категории, лимиты | `presets.py` | — (код) |
| замена командной строки сервера | `src/.env` → окружение процесса при старте | перезапуск |
| процесс сервера | один вызов | — |
| страницы сайта | один вызов инструмента | — |
| каталог инструментов | один ход (запрашивается в начале хода) | — |
| промежуточные сообщения раундов (`tool_calls`, результаты) | один ход | — |
| вызовы последнего хода (для панели) | ответ агента (`AgentReply`), как метрики последнего вызова | ничего: на диск не едут |
| положение «Инструменты MCP в запросе» | агент | ничего: у нового, восстановленного агента и у ветки — **включено** |
| финальный ответ по статье | история (стек и файл сессии) | как весь диалог |

Почему по умолчанию включено: так делали все прошлые переключатели дня (слои памяти, задача, инварианты), и именно это поведение показывает день. Выключенный переключатель — база сравнения «без FAQ» и для недели 5.

### 2.8. Сколько это стоит

- **Токены схем в каждом раунде.** Описания и схемы двух инструментов уходят в запрос каждого раунда — это новая корзина `tools` (§6). Ход без вызова инструментов стоит на эту корзину дороже, чем раньше.
- **Лишние раунды модели.** Ход с двумя вызовами — три запроса к модели, и каждый следующий длиннее предыдущего на результаты инструментов (список вопросов — тысячи токенов). Стоимость хода — сумма раундов.
- **Время**: каталог и каждый вызов — запуск процесса и страницы сайта (§2.4).
- **Вызовов модели служебных работ это не добавляет**: раунды — части основного запроса, а не служебные работы (§5.7).

Точные числа — в замер (§7.4) и в журнал ходов (§8.5).

### 2.9. Что проверено до реализации

Проверено при написании спецификации (22-23.09.2026, во временном каталоге; в репозиторий ничего не попало):

- **Сайт** (`curl`): все числа §2.1. Страница категории отдаёт по 5 статей на раздел и `span.item-count`; раздел из 13 статей — две страницы по 10 (`li.next` → `…/page/2`); статья открывается по адресу без хвоста после номера; в крошках статьи 20 Strong — категория `33000138717`; robots.txt — как в §2.1.
- **Прототип сервера на SDK 2.2.0** (`MCPServer`, `@server.tool()`, `server.run("stdio")`; httpx, разбор регулярными выражениями) против `Client` из `mcp_client` с тем же `StdioServerParameters`:
  - соединение за 0,38 с, **протокол 2026-07-28 через `server/discover`**;
  - `faq_questions` без фильтра — 82 строки, 8 570 символов, 4,2 с (7 запросов к сайту); с `section="patches"` — две строки; `faq_article(33000210180)` — 1,75 с, текст ответа издателя; статья 20 Strong отклонена проверкой крошек;
  - неверный тип аргумента (`"abc"` вместо числа) — SDK сам отвечает `isError: true` с текстом ошибки валидации pydantic; сервер до функции не доходит;
  - **`FastMCP` в SDK v2 переименован в `MCPServer`** (`from mcp.server.mcpserver import MCPServer`); `from mcp.server.fastmcp import FastMCP` падает с сообщением о миграции;
  - функция, возвращающая `str`, по умолчанию получает `outputSchema` и `structuredContent` (`{"result": …}`); с `structured_output=False` инструмент текстовый;
  - SDK сервера по умолчанию пишет в stderr строки уровня INFO с форматированием rich, в том числе каждую строку httpx «HTTP Request: GET …» — в терминале приложения это шум (§3.6);
  - по документации исключений SDK: текст исключения доходит до клиента **только у `ToolError`**; у любого другого клиент видит только «Error executing tool <имя>» (§3.5);
  - импорт `mcp.server.mcpserver` и `httpx` — ≈0,5 с процессорного времени, это и есть цена запуска.
- **DeepSeek** (SDK `openai`, ключ проекта, копеечные вызовы):
  - `deepseek-flash`, thinking off: на просьбу открыть статью — `finish_reason=tool_calls`, аргументы строкой `{"article_id": 33000210180}`; второй раунд с сообщением `tool` — ответ по результату, `stop`;
  - `deepseek-v4-pro`, thinking on: `tool_calls` в первом раунде; второй раунд **и с `reasoning_content`, и без него** — `stop`, без 400; следующий ход с историей из одного текста и `tools` — без 400 (§2.6);
  - `tool_choice="none"` на обеих моделях — ответ текстом без вызова.
- **Имена**: модулей `faq_server` нет ни в стандартной библиотеке, ни среди установленных пакетов.

**Не проверено при написании**: настоящий сервер на `html.parser`, агент с циклом раундов и интерфейс. Их прогон — часть реализации (§11); расхождения с этим разделом записываются в замер как есть.

**Расхождения, найденные на прогоне реализации** (23.09.2026, подробно — замер у `FAQ_MCP`): текст `ToolError` доходит до клиента, но SDK дописывает к нему префикс «Error executing tool <имя>: »; `MCPServer` объявляет возможности prompts, resources и tools, а не одну tools; схемы двух инструментов — ≈495 токенов, а не ≈310.

## 3. Новый сервер `src/faq_server.py`

### 3.1. Что это за файл

- **Отдельная программа, а не модуль приложения.** Её запускает `mcp_client` процессом (`python faq_server.py …`), приложение её **не импортирует**, и она не импортирует ничего из проекта. В графе зависимостей её нет — как нет `app_week1.py`. Правило «SDK `mcp` импортирует только `mcp_client.py`» уточняется: **клиентскую часть SDK** импортирует только `mcp_client.py`, серверную — только `faq_server.py`.
- **Знает портал Freshdesk, но не Too Many Bones.** Адрес портала, id категории и её ожидаемое имя приходят аргументами командной строки из `presets.FAQ_MCP` (§7.1). Разметка портала — константы в начале файла (§3.4), чтобы смена вёрстки правилась в одном месте. Слов «Too Many Bones», «Chip Theory» и «33000133540» в файле нет.
- **Состояния между вызовами нет**: процесс живёт одно соединение, кэша страниц нет.
- **Имя** — `faq_server.py`: такого модуля нет ни в стандартной библиотеке, ни среди установленных пакетов (проверено, §2.9). Файл лежит в `src/` рядом с приложением: так его находит `presets.py` и запускает тот же интерпретатор venv.
- **Строки — по-русски** (правило репозитория): описания инструментов и параметров, тексты ошибок, логи. Содержимое FAQ остаётся английским, как на сайте.

### 3.2. Командная строка

```
python faq_server.py --base-url https://support.chiptheorygames.com --category 33000133540 --category-name "Too Many Bones"
```

| Аргумент | Смысл |
| --- | --- |
| `--base-url` | адрес портала без завершающего `/` |
| `--category` | id категории — строка цифр; другая строка — ошибка `argparse` при старте (процесс завершится, `mcp_client` покажет сбой стадии «соединение», причина — в терминале) |
| `--category-name` | ожидаемое имя категории: сверяется с заголовком её страницы и подставляется в описания инструментов |

Разбор — `argparse`. При старте сервер **в сеть не ходит**: `tools/list` отвечает сразу, и каталог доступен без сети. Сайт читается только на `tools/call`.

### 3.3. Сервер и инструменты

```python
server = MCPServer(name="toomanyrules-faq", version="1.0.0", log_level="WARNING")


@server.tool(
    title="Вопросы FAQ",
    description=QUESTIONS_DESCRIPTION.format(name=args.category_name),
    annotations=ToolAnnotations(read_only_hint=True, destructive_hint=False,
                                idempotent_hint=True, open_world_hint=True),
    structured_output=False,
)
async def faq_questions(
    section: Annotated[str, Field(description=SECTION_DESCRIPTION)] = "",
) -> str: ...


@server.tool(
    title="Статья FAQ",
    description=ARTICLE_DESCRIPTION.format(name=args.category_name),
    annotations=...,            # те же
    structured_output=False,
)
async def faq_article(
    article_id: Annotated[int, Field(description=ARTICLE_ID_DESCRIPTION)],
) -> str: ...


server.run("stdio")
```

- **SDK v2 — `MCPServer`, а не `FastMCP`** (§2.9). Примеры из интернета на `from mcp.server.fastmcp import FastMCP` — это v1; их не копировать.
- **`structured_output=False`**: результат — текст для модели. Без этого флага SDK добавил бы `outputSchema` и `structuredContent` с тем же текстом, который никто не читает.
- **Аннотации честные**: инструменты только читают, повторный вызов безопасен, мир открытый (сайт). Для контраста: у bgg-mcp все аннотации стоят по умолчанию mcp-go — `destructiveHint: true` у инструментов, которые только читают (день 16, §2.1).
- **`log_level="WARNING"`** — §3.6.

Описания — черновик, который исполнитель может уточнить по живому прогону. **Каждое изменение по сбою прогона записывается строкой в комментарии у константы** — правило промптов дней 10-15: описание инструмента и есть промпт.

На прогоне реализации черновик уточнён дважды (записано у констант в `faq_server.py`): `QUESTIONS_DESCRIPTION` — «вызывай перед **каждым** ответом о правилах, даже если ответ кажется известным» и «статьи нет — скажи, что в FAQ этого нет» (с черновиком `deepseek-flash` на И2 и И4 инструменты не звал, на И2 ответил неверно); `SECTION_DESCRIPTION` — «это фильтр по названию раздела, а не поиск по теме: вопрос не про героя — без фильтра» (обе модели передавали `section="Poison"` и открывали не те статьи).

```python
QUESTIONS_DESCRIPTION = (
    "Список вопросов официального FAQ издателя по игре {name}: номер статьи, раздел и вопрос "
    "(по-английски). Вызывай перед ответом на вопрос о правилах, чтобы найти подходящие "
    "статьи, затем открой нужную через faq_article. Если вопрос про конкретного героя — "
    "сузь список параметром section."
)
SECTION_DESCRIPTION = (
    "Необязательный фильтр по разделу: часть английского названия, без учёта регистра — "
    "имя героя (Patches, Tink, Picket), Battle, Loot, Tyrants. Пусто — все вопросы."
)
ARTICLE_DESCRIPTION = (
    "Текст статьи официального FAQ по игре {name} по её номеру из faq_questions: вопрос, "
    "раздел, ссылка и ответ издателя (по-английски). Отвечая игроку по статье, перескажи "
    "ответ по-русски и дай ссылку на статью."
)
ARTICLE_ID_DESCRIPTION = "Номер статьи — первое поле строки из faq_questions."
```

### 3.4. Чтение сайта

- **HTTP — `httpx.AsyncClient`**: таймаут на запрос `HTTP_TIMEOUT_S = 10`, переход по редиректам, не больше `HTTP_CONCURRENCY = 4` запросов одновременно (`asyncio.Semaphore`) — вежливость к чужому сайту. Повторов нет: сбой — ошибка инструмента.
- **User-Agent — только ASCII** (заголовок HTTP кириллицу не примет): `TooManyRules-FAQ-MCP/1.0 (AI Advent Challenge study project)`.
- **Только адреса категории, разделов и статей** этой категории. `/support/search` не используется (robots.txt).
- **Разбор — `html.parser` из стандартной библиотеки**, без новых зависимостей (BeautifulSoup не ставим). Регулярные выражения для извлечения блоков — нет: прототип на них работал, но вложенные теги и сущности HTML надёжнее разбирает парсер. Маркеры разметки — константы в начале файла:

| Константа | Что ищем |
| --- | --- |
| `CATEGORY_HEADING` | `h2.solution-category-heading` — имя категории |
| `SECTION_BLOCK` | `section.article-list` на странице категории |
| `SECTION_LINK` | ссылка `/support/solutions/folders/<id>` в `div.solution-list-title`: имя раздела — атрибут `title`, число статей — `span.item-count` |
| `ARTICLE_LINK` | ссылка `/support/solutions/articles/<id>…`; вопрос — атрибут `title` на странице категории и текст ссылки на странице раздела |
| `NEXT_PAGE` | ссылка в `li.next` пагинации раздела |
| `ARTICLE_TITLE` | `h2` над телом статьи |
| `ARTICLE_BODY` | `article#article-body` |
| `BREADCRUMB_LINK` | ссылки `a.breadcrumbs-btn` в `div.breadcrumbs`: категория и раздел статьи |

**`faq_questions`**:

1. Страница категории. Имя из заголовка сверяется с `--category-name` (§3.5).
2. По каждому разделу — id, имя, объявленное число статей и статьи, показанные на странице категории.
3. Раздел, где показано меньше объявленного, дочитывается со своей страницы по всем страницам пагинации. Такие разделы читаются параллельно (с потолком одновременных запросов).
4. Порядок — как на сайте: разделы в порядке страницы категории, статьи внутри раздела — в порядке страницы. Параллельное чтение порядок не меняет.
5. **Проверка полноты**: если собрано не столько статей, сколько объявлено у раздела, в конец ответа добавляется строка «⚠️ Раздел Battle: на сайте 7, прочитано 6». Ответ при этом не ошибка — список полезен и неполным.
6. Фильтр `section` — подстрока имени раздела без учёта регистра. Дочитываются только разделы, которые прошли фильтр.

Формат ответа:

```
FAQ «Too Many Bones» (https://support.chiptheorygames.com/support/solutions/33000133540): 82 вопроса в 24 разделах.
Строка: номер статьи · раздел · вопрос.
33000210058 · Battle · Do Baddies re-roll Active Def on their turn?
33000210144 · Battle · Can Gearlocs and Baddies roll Atk dice without a valid target in order to acquire Bones?
…
```

С фильтром — «Разделы по фильтру «patches»: Patches — 2 вопроса.» и строки. Если фильтр не подошёл ни к одному разделу — это **не ошибка**, а ответ «Разделов с «xyz» нет. Разделы: Battle, Baddie Skills and Encounter Terms, …» — модель может повторить вызов с правильным именем. Лишние пробелы в вопросах схлопываются, сущности HTML раскрываются.

**`faq_article`**:

1. Страница `/support/solutions/articles/<article_id>`.
2. В крошках должна быть ссылка на нашу категорию (§3.5).
3. Вопрос — `h2`, раздел — последняя крошка, текст — тело статьи: абзацы (`p`, `div`), переносы (`br`) и пункты списков (`li` — с «- ») дают переводы строк. Картинки — строкой «[изображение]», у ссылок остаётся текст. Пустые строки подряд схлопываются.
4. Длину сервер не режет: статьи FAQ короткие. Потолок держит приложение (§5.5).

Формат ответа:

```
Вопрос: Q: Can Patches heal one of Tink's bots?
Раздел: Patches
Ссылка: https://support.chiptheorygames.com/support/solutions/articles/33000210180
Ответ издателя:
No! Patches can only heal Gearlocs - he cannot heal Allies such as Ghillie's Pets, Tink's Bots, or Nightshade. …
```

Ссылка — канонический адрес без хвоста после номера: он работает (§2.9) и не зависит от того, как сайт сейчас транслитерирует заголовок.

### 3.5. Ошибки инструментов

Ожидаемый сбой — **`ToolError`** из `mcp.server.mcpserver.exceptions` с текстом по-русски: только его текст доходит до клиента (§2.9). SDK превращает его в результат с `isError: true`, агент отдаёт этот текст модели (§5.5), и модель может объяснить игроку, что FAQ недоступен.

| Что случилось | Текст `ToolError` (пример) |
| --- | --- |
| сеть: таймаут, нет соединения | «сайт FAQ недоступен: ConnectTimeout при запросе /support/solutions/33000133540» |
| ответ не 200 | «сайт FAQ ответил 503 на /support/solutions/folders/33000202481» |
| статьи нет (404) | «статьи 123 в FAQ нет (сайт ответил 404)» |
| имя категории не то | «категория 33000133540 на сайте называется «…», ожидалась «Too Many Bones» — проверьте настройки сервера в presets.py» |
| статья из другой категории | «статья 33000285781 — не из FAQ «Too Many Bones»: по хлебным крошкам она в категории «20 Strong»» |
| разметка не разобрана (нет заголовка категории, нет тела статьи) | «разметка страницы не разобрана: не найден article#article-body на /support/solutions/articles/…» |

- Аргумент не того типа (`article_id="abc"`) сервер не проверяет сам — это делает SDK по схеме (§2.9), и ответ тоже `isError`.
- Любое другое исключение — ошибка в коде сервера. SDK отдаёт клиенту только «Error executing tool …», а трассировку пишет в stderr. Так и оставляем: трассировка чужому процессу не нужна, а в терминале она есть.

### 3.6. Логи сервера

stdout сервера — канал JSON-RPC, поэтому **логи пишутся только в stderr**, а он идёт в терминал приложения как есть (день 16, §4.6). Строки короткие, с префиксом `[FAQ-сервер]`, одна строка на запрос к сайту и одна на вызов:

```
[FAQ-сервер] GET /support/solutions/33000133540 → 200 за 0.61 с
[FAQ-сервер] GET /support/solutions/folders/33000202498/page/2 → 200 за 0.48 с
[FAQ-сервер] faq_questions(section=""): 82 вопроса, 24 раздела, 7 запросов, 3.95 с
[FAQ-сервер] faq_article(33000285781): отказ — статья не из FAQ «Too Many Bones» (категория «20 Strong»)
```

Логи SDK сервера и httpx — уровня `WARNING` (`MCPServer(log_level="WARNING")`, `logging.getLogger("httpx").setLevel(logging.WARNING)`): их строки INFO с форматированием rich в терминале приложения — шум (§2.9).

## 4. Что меняется в `src/mcp_client.py`

Модуль остаётся листом графа, единственным местом импорта клиентской части SDK и не знает ни про FAQ, ни про LLM. `list_tools()` не меняется по поведению; общий код запуска, согласования и разбора сбоев выносится во внутренние функции, которыми пользуются обе публичные.

### 4.1. Вызов инструмента: `call_tool(server, name, arguments, *, timeout_s) -> ToolCall`

Одно полное подключение: запуск → согласование → `tools/call` → закрытие. Синхронная, исключений на ожидаемых сбоях не бросает — ровно как `list_tools()`.

```python
STAGE_CALL = "вызов инструмента"        # соединение есть, результата нет


@dataclass(frozen=True)
class ToolCall:
    """Результат одного вызова инструмента — и удачного, и нет."""
    server: str
    launch: Launch
    at: str
    name: str
    arguments: dict
    stage: str = ""             # "" — дошли до конца; иначе запуск / соединение / вызов инструмента
    error: str = ""             # сбой соединения или протокола; "" — ответ получен
    is_error: bool = False      # сервер ответил, но с isError: ошибка самого инструмента
    text: str = ""              # текстовые части content через перевод строки; не текст — «[<type>]»
    server_name: str = ""
    server_version: str = ""
    protocol_version: str = ""
    handshake: str = ""
    connect_s: float = 0.0
    call_s: float = 0.0
    total_s: float = 0.0

    @property
    def ok(self) -> bool:       # ответ получен и это не ошибка инструмента
        return not self.error and not self.is_error
```

- **Две разные неудачи — два поля**: `error` — до ответа не дошли (процесс, протокол, таймаут); `is_error` — сервер ответил, что инструмент не справился (§3.5). Модели уходит и то и другое, но словами разными (§5.5).
- Сбой стадии «вызов инструмента»: `MCPError` на `tools/call`, процесс умер на вызове, таймаут на вызове. Таймаут — `fail_after` на всё подключение, как у `list_tools()`.
- В `arguments` лежит то, что передали. Значения аргументов пишутся в лог: это не секреты, а номер статьи и имя раздела.

### 4.2. Адаптер для агента: `McpToolBox`

Агент не импортирует `mcp_client` (§5.1). Он получает объект, который отвечает протоколу `ToolBox` из `agent.py`; обмен идёт словарями — тот же приём, что у хранилищ (`storage.py` протоколы агента не импортирует):

```python
class McpToolBox:
    """Инструменты одного MCP-сервера для агента: каталог и вызов, каждый раз новое соединение."""

    def __init__(self, server: McpServer, *, timeout_s: float): ...

    @property
    def name(self) -> str: ...          # server.name — для логов агента

    def catalog(self) -> dict:
        # list_tools() → {"ok": bool, "error": str, "elapsed": float,
        #                 "tools": [{"name", "description", "input_schema"}, …]}
        # input_schema — inputSchema из ответа как пришла (из pages, by_alias)

    def call(self, name: str, arguments: dict) -> dict:
        # call_tool() → {"ok": bool, "is_error": bool, "error": str, "stage": str,
        #                "text": str, "elapsed": float}
```

`catalog()` и `call()` тоже не бросают исключений. Каталог при сбое — `ok=False` с текстом `«сбой на стадии «…»: …»`.

### 4.3. Логи

Тем же префиксом `[MCP <имя>]`, что на дне 16; строки подключения и закрытия — как у `list_tools()`:

## 5. Что меняется в `src/agent.py`

### 5.1. Зависимость `tools` и протокол `ToolBox`

```python
class ToolBox(Protocol):
    """Инструменты для function calling (реализация — `mcp_client.McpToolBox`,
    спецификация дня 17, §4.2). Один на процесс и общий для всех агентов.
    Обмен словарями: реализация протокол не импортирует."""

    @property
    def name(self) -> str: ...
    def catalog(self) -> dict: ...
    def call(self, name: str, arguments: dict) -> dict: ...
```

- Конструктор `Agent` получает три новых необязательных параметра в конце: `tools: ToolBox | None = None`, `tool_max_rounds: int = 4`, `tool_result_max_chars: int = 12_000`. Значения по умолчанию — только чтобы агент без `app.py` собирался. Настоящие значения передаёт `app.py` из `presets.py` (§7.2).
- **Без `tools` агент ведёт себя ровно как на дне 16**: ни корзины, ни раундов, ни параметра `tools` в запросе. Так было с каждой необязательной зависимостью.
- Приём тот же, что у хранилищ дня 11: «на процесс один объект из `app.py`». Новый агент, восстановленный агент и ветка (`fork()`) получают тот же `ToolBox`.

### 5.2. Переключатель «Инструменты MCP в запросе»

- `set_tools_in_request(enabled: bool) -> bool` под `@_locked`. Возвращает `False`, если `tools` нет или значение не изменилось. Лог: `[#3 Базовый · s003] инструменты MCP в запросе: вкл → выкл`.
- Свойство `tools_in_request`. По умолчанию **включено** — у нового, восстановленного агента и у ветки (§2.7). На диск и в checkpoint положение не едет; `reset()` его не трогает — это не диалог.
- **Выключено — значит, нет ни каталога, ни корзины, ни параметра `tools`**: запрос такой же, как на дне 16. Это и есть база сравнения.

### 5.3. Каталог хода

В `ask()` — после всех служебных работ (трекер остаётся последним из них) и до сборки запроса: схемы нужны оценке токенов.

1. Если `tools` нет или переключатель выключен — каталога нет, `tools_note = "выключены"` (или `""`, если `tools` нет).
2. `catalog = self._tools.catalog()` — одно подключение к серверу, лог в `mcp_client`.
3. Сбой каталога **ход не отменяет**: запрос уходит без `tools`, `tools_note = "каталог не получен: сбой на стадии «запуск»: …"`, в логе агента — `WARNING`. Правило дня 9: деградация — в сторону «как раньше», а не отказа.
4. Успех — схемы в формате §2.6: `{"type": "function", "function": {"name", "description", "parameters": input_schema}}`, в порядке каталога. `tools_note = "faq: 2 инструмента за 0.41 с"`.
5. Имена инструментов каталога запоминаются на ход: вызов с другим именем не уходит на сервер (§5.5).

### 5.4. Оценка токенов

- Строка схем для оценки — `json.dumps(specs, ensure_ascii=False)`; её считает `tokens.count_request(..., tools_json=…)` (§6) через `_count_messages(messages, tools_json=…)`. Правило дня 8 «посчитали и отправили — одно и то же» сохраняется: в оценку идут те же схемы, что в параметр `tools`.
- Оценка до запроса — **только для первого раунда**: промежуточные сообщения появляются по ходу, и считать их заранее не из чего. Калибровка (`calibration`) и строка «оценка/факт prompt» в логе сравнивают оценку с `prompt_tokens` **первого** раунда.
- `context_usage()` для панели считает корзину `tools` по схемам **последнего успешно полученного каталога** этого агента, если переключатель включён; пока каталога не было — 0. Панель подписывает её «по каталогу прошлого хода» (§8.3): чистые методы в сеть не ходят (правило дня 9).

### 5.5. Цикл раундов

```python
specs = …                                   # §5.3; [] — без инструментов
messages, view = self._context_view(...)    # как раньше, плюс tools_json
rounds, calls = [], []
while True:
    number = len(rounds) + 1
    params = {}
    if specs:
        params["tools"] = specs
        if number > self._tool_max_rounds:
            params["tool_choice"] = "none"  # финальный раунд: только ответ
    response = client.chat.completions.create(model=…, messages=messages, extra_body=…, **self._optional_params(), **params)
    rounds.append(ModelRound(...))          # токены, время, finish_reason, число вызовов
    message = response.choices[0].message
    if response.choices[0].finish_reason != "tool_calls" or not message.tool_calls:
        break                               # финальный ответ — text этого раунда
    messages = messages + [_assistant_with_calls(message)]   # content, tool_calls, reasoning_content (если есть)
    for tool_call in message.tool_calls:
        record, content = self._run_tool_call(number, tool_call, known_names)
        calls.append(record)
        messages.append({"role": "tool", "tool_call_id": tool_call.id, "content": content})
```

- **Раунд — настоящий вызов API**: каждый раунд идёт в счётчики агента и процесса как отдельный вызов (`totals.calls`), с токенами и стоимостью. Отдельной служебной работой он не считается: цикл — это основной запрос хода, растянутый на несколько вызовов (§5.7).
- **`_assistant_with_calls()`** — словарь `{"role": "assistant", "content": message.content or "", "tool_calls": [...]}` плюс `reasoning_content`, если модель его вернула (§2.6). В комментарии у функции записано правило DeepSeek про `reasoning_content` с `tools` и что проверено 22.09.2026.
- **`_run_tool_call()`** исключений не бросает. Порядок проверок:
  1. имя не из каталога хода → на сервер не ходим, модели: «Инструмента <имя> нет. Доступны: faq_questions, faq_article»;
  2. `arguments` не разбирается `json.loads` или это не объект → на сервер не ходим, модели: «Аргументы не разобраны: <причина>. Пришло: <строка>»;
  3. `self._tools.call(name, arguments)`:
     - `ok` → текст результата;
     - `is_error` → «Ошибка инструмента: <текст сервера>»;
     - сбой соединения → «Инструмент недоступен: сбой на стадии «…»: …».
- **Потолок длины результата** — `tool_result_max_chars`: длиннее — обрезается, а в конец дописывается «[обрезано приложением: показано N из M символов]». Обрезка видна модели, в панели и в логе. 12 000 символов с запасом вмещают полный список вопросов (8,5 тыс.), а чужой сервер не может молча раздуть запрос.
- **Потолок раундов** — `tool_max_rounds` раундов с доступными инструментами. Если и последний из них закончился `tool_calls`, вызовы этого раунда выполняются, и уходит ещё один, финальный раунд с `tool_choice="none"` (проверено, §2.9). Всего раундов в ходе — не больше `tool_max_rounds + 1`. В лог — `WARNING` «потолок раундов: ответ без новых вызовов».
- **Несколько вызовов в одном раунде** выполняются последовательно, в порядке `tool_calls`. Сообщение `tool` уходит на каждый вызов, даже на отклонённый: API требует ответ на каждый `tool_call_id`.
- **`finish_reason="length"`** на любом раунде — ход заканчивается этим раундом, как и сегодня: текст (возможно, пустой или оборванный) идёт в историю, предупреждение — в панель и лог.
- **Сбой API на раунде > 1** — ход неудачен целиком, как сбой основного вызова сегодня: стек не меняется, `AgentReply(ok=False)` несёт уже сделанные вызовы инструментов и раунды, чтобы в панели было видно, на чём оборвалось. Счётчики успешных раундов уже учтены — потраченное осталось потраченным.
- **Всё — под замком хода**: `ask()` уже `@_locked`, и вызовы инструментов идут внутри него. Длинный ход держит замок дольше — это то же правило, что для служебных работ.

### 5.6. Что попадает в историю

- В стек и файл сессии — **только вопрос и финальный текст**, как сегодня. Сообщения с `tool_calls` и `role: "tool"` живут только в пределах хода.
- Почему так:
  - формат файла сессии, стратегии (свёртка, окно, факты считают пары сообщений), разбор памяти, трекер (`len(history)` — место в истории), checkpoint'ы и `_count_messages()` (разбор по ролям) рассчитаны на пары «вопрос/ответ». Сообщения инструментов в стеке задели бы всё это разом;
  - результат инструмента уже пересказан в ответе, и ссылка на статью в нём есть.
- Цена: на следующем ходе модель не видит текста статьи — только свой пересказ. Если уточнение требует статьи, модель вызовет инструмент снова. Это записывается в «не делаем» (§14).
- `reasoning` ответа — рассуждения всех раундов подряд, с разделителями «— раунд N —». В стек они не идут, как и сегодня.

### 5.7. Ответ, журнал ходов и счётчики

Новые типы — в `agent.py`, рядом с `ServiceCall`:

```python
@dataclass(frozen=True)
class ModelRound:
    number: int
    elapsed: float
    prompt_tokens: int | None
    completion_tokens: int | None
    cost_usd: float | None
    finish_reason: str | None
    tool_calls: int                 # сколько вызовов попросила модель в этом раунде
    tool_choice: str = ""           # "none" — финальный раунд после потолка


@dataclass(frozen=True)
class ToolCallRecord:
    round: int
    call_id: str
    name: str
    arguments: str                  # строка JSON, как прислала модель
    status: str                     # «ок» | «ошибка инструмента» | «инструмент недоступен» | «аргументы не разобраны» | «нет такого инструмента»
    text: str                       # что ушло модели (после обрезки)
    chars: int                      # длина результата до обрезки
    truncated: bool
    elapsed: float                  # с запуском сервера; 0 — на сервер не ходили
```

Поля в конце `AgentReply` (правило дней 8-15 — в конце и с умолчаниями):

| Поле | Что |
| --- | --- |
| `tools_note: str = ""` | что с каталогом этого хода (§5.3) |
| `tool_specs_tokens: int = 0` | оценка корзины `tools` |
| `rounds: tuple[ModelRound, ...] = ()` | все раунды хода; для хода без инструментов — один раунд |
| `tool_calls: tuple[ToolCallRecord, ...] = ()` | все вызовы хода по порядку |
| `tool_elapsed: float = 0.0` | каталог и все вызовы вместе |

Прежние поля ответа меняют смысл аккуратно и один раз:

- `prompt_tokens`, `completion_tokens`, `total_tokens`, `cost_usd`, `elapsed` — **суммы по раундам**: цена и время хода. `elapsed` — только время модели, время инструментов — в `tool_elapsed`.
- `finish_reason` и `text` — последнего раунда.
- `request_tokens` — оценка первого раунда (§5.4).
- Кэш промпта — сумма по раундам (раунды одного хода — почти один и тот же префикс, и попадания видно).

Поля в конце `TurnStats`: `tool_rounds: int = 0`, `tool_calls: int = 0`, `tools_tokens: int = 0` (корзина), `tool_elapsed: float = 0.0` и — добавлено при реализации — `first_prompt_tokens: int = 0`, `prompt_tokens` первого раунда. Остальные колонки журнала — как сегодня, по суммам хода; «оценка/факт» сравнивает оценку с `first_prompt_tokens`, иначе на ходе с инструментами она сравнивала бы оценку первого раунда с суммой трёх. По той же причине «ответ модели: оценка по тексту» в логе и панели сравнивается с `completion_tokens` последнего раунда — текст его, а сумма включает токены вызовов.

1. **Свой сервер**: `src/faq_server.py` — регистрация двух инструментов (`@server.tool`), параметры с описаниями (`Annotated[…, Field(description=…)]`), возврат текста; проверка категории и крошек (20 Strong).
2. **Источник**: страница FAQ Too Many Bones на сайте издателя; чем опасен корень FAQ (папка «Too Many Bones» у 20 Strong).
3. **Каталог по кнопке**: два инструмента, параметры и описания, протокол 2026-07-28 без рукопожатия — рядом с bgg-mcp дня 16 на `initialize`.
4. **Агент вызывает инструмент**: И1 — в блоке «Инструменты последнего хода» `faq_questions` → `faq_article`, три раунда; ответ по-русски со ссылкой на статью; открыть ссылку — это та самая статья.
5. **Терминал**: строки агента (раунды), `mcp_client` (подключения) и сервера (запросы к сайту) — один ход целиком.
6. **Решает модель**: И3 — ни одного вызова; И4 — статьи нет, ассистент так и говорит.
7. **Результат используется**: И5 — тот же вопрос без инструментов, ответ из общих знаний; журнал ходов — сколько стоили раунды и схемы.

## 13. Критерии приёмки

## 14. Что сознательно НЕ делаем на этом шаге

- **Не держим постоянного соединения** и не храним процесс сервера между вызовами: каталог и каждый вызов — новое подключение. Ни пула, ни фонового цикла событий, ни `start_blocking_portal`.
- **Не кэшируем** ни каталог, ни страницы сайта, ни список вопросов — ни в сервере, ни в приложении, ни на диске. Сайт читается при каждом вызове.
- **Не пишем промежуточные сообщения в историю**: `tool_calls` и результаты инструментов не попадают ни в стек, ни в файл сессии, ни в checkpoint'ы, ни в ветки. Не храним `reasoning_content` в истории и не меняем формат файла сессии.
- **Не даём агенту инструменты BoardGameGeek**: сервер дня 16 остаётся только с каталогом по кнопке (для вызовов ему нужен ключ BGG, и это отдельный шаг). Несколько серверов у агента, выбор сервера и выбор отдельных инструментов в интерфейсе не делаем — только общий переключатель.
- **Не используем поиск сайта** (`/support/search` закрыт в robots.txt) и не пишем своего поиска по словам: подходящий вопрос выбирает модель по списку.
- **Не читаем корень FAQ и другие категории**, не делаем сервер «для любой игры издателя»: одна категория из `presets.py`.
- **Не используем API Freshdesk** (нужен ключ агента поддержки) и не ставим BeautifulSoup и другие парсеры.
- **Не делаем повторов запросов к сайту**, обхода защиты от ботов и подмены браузера: сбой — ошибка инструмента.
- **Не делаем ручного вызова инструмента в интерфейсе** (форма «имя + аргументы»): вызывает агент; для ручной проверки — REPL и Inspector.
- **Не показываем вызовы инструментов в самом чате** (сообщения с `metadata` Gradio): чат рендерится из истории, а в истории их нет. Вызовы видны в дебаг-панели.
- **Не меняем системные промпты** пресетов и не добавляем блок «когда звать инструменты» в запрос: это работа описаний инструментов.
- **Не заставляем модель звать инструмент** (`tool_choice="required"` или выбор конкретного инструмента) и не вызываем инструменты кодом по ключевым словам вопроса: решает модель.
- **Не отдаём инструменты служебным работам** (стратегия, страж, разбор памяти, роутер, трекер).
- **Не запрашиваем ресурсы и промпты**, не делаем HTTP-транспорт, не подписываемся на уведомления, не передаём `instructions` сервера в запрос.
- **Не чистим результаты инструментов от возможных инструкций внутри текста**: источник — сайт издателя, результат идёт сообщением `tool`, а не системным. Защита от инъекций через инструменты — отдельная тема.
- **Не оцениваем кодом качество ответов и правильность выбора статьи**: сверяет человек по сценарию (§11).
- **Не пишем отдельного документа проверки**: формат дня — видео + код; факты прогона — в замере (§7.4).
- Не делаем RAG, эмбеддингов и индексов — это неделя 5. Не пишем тестов и линтера.

Не расширяй объём дня сверх сервера из §3, вызова и адаптера из §4, цикла из §5, корзины из §6, секции `presets.py` из §7, переключателя, блока и перекладки аккордеонов из §8, зависимости и README из §10.
