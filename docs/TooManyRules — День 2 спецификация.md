# TooManyRules — спецификация дня 2

Тема: Формат ответа

Эта спецификация — техническое задание для AI\-ассистента, который будет писать код.

## 1\. Задание челленджа (день 2)

Текст задания — платный контент челленджа, поэтому здесь не копируется. См. локально (не в git\-репозитории): `tasks/AI Advent Challenge_02.txt`.

## 2\. Что делаем конкретно для TooManyRules

Берём **один и тот же вопрос по правилам** и отправляем его в DeepSeek API дважды — с разной конфигурацией — чтобы наглядно показать разницу.

Фиксированный вопрос для теста (можно заменить на реальный спорный момент из своих партий — тогда ещё нагляднее):

```
Может ли гирлок ходить по диагонали?
```

**Вариант A — без ограничений.** Тот же системный промпт, что и в дне 1 (см. спецификацию дня 1), пользовательский вопрос как есть, без параметров `max_tokens`/`stop`, без требований к формату.

**Вариант B — с ограничениями.** Тот же вопрос, но:

- **формат ответа** задан явно через инструкцию в системном промпте \+ структурированный вывод в виде JSON:
  
  ```json
  {
    "rule_summary": "краткое изложение правила в 1-2 предложениях",
    "details": "более подробное пояснение, если нужно",
    "confidence": "high | medium | low"
  }
  ```
  
  (поле `confidence` — честная самооценка модели; пока без RAG модель может ошибаться, это нормально и ожидаемо на этом этапе);

- **ограничение длины** — параметр `max_tokens` в запросе к API (например, 150) в дополнение к явной инструкции в промпте «уложись в 2\-3 предложения»;

- **условие завершения** — параметр `stop` в запросе к API с выбранной стоп\-последовательностью (например, `"###END###"`), при этом системный промпт инструктирует модель заканчивать ответ этой последовательностью сразу после JSON\-объекта.

Оба вызова логируются и выводятся рядом — в простом Gradio\-интерфейсе с двумя полями вывода на один инпут.

## 3\. Системные промпты

**Вариант A (без ограничений)** — как в дне 1, без изменений.

**Вариант B (с ограничениями)** — дополняет промпт дня 1:

```
Дополнительно к своей роли: отвечай СТРОГО в формате JSON со следующими
полями:
{
  "rule_summary": "краткое изложение правила в 1-2 предложениях",
  "details": "более подробное пояснение, если нужно",
  "confidence": "high | medium | low"
}

Не добавляй никакого текста до или после JSON-объекта. Сразу после
закрывающей скобки JSON выведи строку "###END###" и ничего больше.
Уложись в 2-3 предложения суммарно в полях rule_summary и details.
```

## 4\. Технические требования

- Тот же стек, что и в дне 1: Python, DeepSeek API (OpenAI\-совместимый клиент), Gradio.
- Параметры API для варианта B: `max_tokens` и `stop` передаются явно в запрос (не только текстовой инструкцией в промпте) — задание прямо требует both подходов (явная инструкция и технический параметр), важно показать оба.
- Добавляем весь новый функционал в постоянный интерфейс дня 1.
- API\-ключ — как и раньше, только через `.env`, не коммитить.

## 5\. Что должно быть видно в видео (день 2)

1. Запуск скрипта/приложения дня 2.
2. Один и тот же вопрос отправляется дважды — без ограничений и с ограничениями.
3. Видно оба ответа: первый — свободный текст произвольной длины и формы; второй — валидный JSON фиксированной структуры, короткий, с явным маркером завершения `###END###`.
4. Краткий комментарий (в видео или в коде), в чём разница и почему второй ответ предсказуемее по структуре.

## 6\. Критерии приёмки

- Один и тот же пользовательский вопрос используется в обоих вызовах.
- Вариант B возвращает валидный JSON, парсящийся без ошибок (стоит добавить проверку `json.loads()` на стороне кода и вывести результат парсинга — если распарсилось, показать это явно).
- В варианте B реально применены оба технических параметра (`max_tokens`, `stop`), а не только текстовая инструкция.
- Ответ варианта B заметно короче и предсказуемее по форме, чем вариант A.

## 7\. Что сознательно НЕ делаем на этом шаге

- RAG / реальную базу правил — неделя 5 (поэтому поле `confidence` в структуре ответа осознанно условное, «на глаз» от модели, а не основано на найденном источнике).
- Разные стратегии рассуждения («пошагово», «консилиум экспертов») — это день 3.
- Память между запросами/сессиями — недели 2\-3.

Не расширяй объём задания сверх сравнения «без ограничений / с ограничениями» на одном и том же вопросе.
