Тема: Температура генерации

Эта спецификация — техническое задание для AI-ассистента, который будет писать код.

## 1. Задание челленджа (день 4)

Текст задания — платный контент челленджа, поэтому здесь не копируется. См. локально (не в git-репозитории): `tasks/AI Advent Challenge_04.txt`.

## 2. Что делаем конкретно для TooManyRules

Берём один и тот же вопрос по правилам Too Many Bones и прогоняем его через DeepSeek API при трёх значениях `temperature`. Чтобы разница была видна не только на факте, но и на стиле изложения (задание просит сравнить в том числе «креативность»), вопрос не должен требовать голого факта в одно слово — нужно оставить модели немного простора для иллюстрации: объяснение правила + пример игровой ситуации.

Пример вопроса (важна структура «факт + иллюстрация» и важно не менять вопрос в процессе одного прогона сравнения):

```
Объясни как работает Отравление в Too Many Bones простыми словами, как будто
объясняешь новому игроку, и приведи короткий пример игровой ситуации,
описывающей это правило.
```

Один запуск сравнения — **9 обращений к API**: 3 повтора на каждое из 3 значений `temperature` (0 / 0.7 / 1.2). Повторы внутри одной температуры нужны, чтобы вообще было что сравнивать по критерию «разнообразие» — единственный ответ на температуру ничего не говорит о разбросе, только несколько ответов подряд при одной и той же температуре показывают, насколько она стабильна или, наоборот, даёт расхождения.

Системный промпт и вопрос не меняются между всеми 9 вызовами — единственная переменная это `temperature`, как и требует задание («выполните один и тот же запрос»).

## 3. Параметры запросов

- Системный промпт — `SYSTEM_PROMPT` из дня 1, без изменений.
- Модель — `deepseek-chat`, как во всех предыдущих днях.
- `temperature` передаётся явно в каждом вызове API (не текстовой инструкцией в промпте): `0`, `0.7`, `1.2`.
- Остальные параметры (`max_tokens`, `stop` и т.п. из дня 2) не задаются — сравниваем эффект чистой температуры, без побочных ограничений.
- 3 повтора на каждое значение `temperature`.

## 4. Технические требования

- Тот же стек и файл (`src/app.py`), новая вкладка «День 4» добавляется по аналогии с днями 1-3 (`gr.Tab` внутри существующего `gr.Blocks`), остальные вкладки не трогаем.
- Один клик по кнопке делает все 9 вызовов (порядок и синхронность выполнения не принципиальны — задание не про производительность) и логирует каждый вызов в stdout (значение `temperature`, номер повтора, `finish_reason`, длина и текст ответа) — тот же паттерн логирования, что в днях 2-3.
- Вывод — 3 колонки (по одной на каждое значение `temperature`), в каждой колонке 3 текстовых блока с подписанным номером повтора. Никакой автоматической метрики точности/креативности/разнообразия и никакой подсветки «лучшего» варианта кодом — сравнение и выводы делает автор вручную, глядя на 9 ответов (тот же принцип, что и в §7 спецификации дня 3).
- API-ключ — через `.env`, не коммитить.

## 5. Что должно быть видно в видео

1. Запуск скрипта, вкладка «День 4».
2. Все 9 ответов (3 температуры × 3 повтора), с ясно видными подписями температуры и номера повтора.

## 6. Критерии приёмки

- Один и тот же вопрос выполнен при `temperature` 0, 0.7 и 1.2 (задание требует именно эти три значения).
- Для каждой температуры есть несколько повторов, позволяющих оценить разнообразие, а не единственный ответ.

## 7. Что сознательно НЕ делаем на этом шаге

- Не трогаем вкладки/промпты дней 1-3.
- Не тестируем другие параметры сэмплирования (`top_p`, `frequency_penalty`, `presence_penalty` и т.п.) — только `temperature`, как в задании.
- Не считаем автоматические метрики точности/креативности/разнообразия и не подсвечиваем «лучший» ответ кодом — оценка человеческая, как в дне 3.
- RAG / реальную базу правил — неделя 5, точность ответов пока оценивается вручную по бумажной книге правил.
- Не меняем вопрос между температурами/повторами в рамках одного прогона сравнения.

Не расширяй объём задания сверх сравнения трёх температур на одном и том же запросе.
