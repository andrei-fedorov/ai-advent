# Неделя 7 — продукты с LLM

Небольшие продукты AI Advent Challenge живут здесь независимо от TooManyRules: своё окружение, зависимости и данные, проект передаётся через `--repo`.

## Ассистент разработчика (день 31)

`devhelp` отвечает в терминале по документации проекта. Перед каждым вопросом ищет пять выдержек из Markdown (e5-base и реранкер bge), получает ветку через свой MCP-сервер git. Модель может вызвать статус, последние коммиты и diff. Каждый вопрос независим; ссылки `[N]` в ответе связываются с путём, строкой, разделом и днём документа. Подробности — в [спецификации](docs/День%2031%20спецификация.md).

## Запуск

Нужны Python 3.14 и `uv`. В `.env` этого каталога задайте `LLM_API_KEY`. Необязательные `LLM_BASE_URL` и `LLM_MODEL` меняют OpenAI-совместимый API; по умолчанию — `https://api.deepseek.com`, `deepseek-flash`.

```bash
./week7/run.sh index
./week7/run.sh index --probe
./week7/run.sh help
./week7/run.sh help "Где в проекте вызывается LLM API?"
```

Первый индекс скачивает около 1,7 ГБ моделей в `data/models/` и занимает около 13 минут на CPU. Он готовит обе модели. Повторная сборка пересчитывает только изменённые файлы, `--full` — все; `--probe` проверяет поиск по готовому индексу без пересборки. Ассистент модели не скачивает.

В корпус входят `README.md`, `docs/*.md`, `week7/README.md`, `week7/docs/*.md`. Код и инструкции агентам не индексируются. Исторические документы помечаются днём; README и архитектура кода — текущим состоянием. При расхождении выдержек модель должна предпочитать более поздние сведения.

```text
devhelp> /help
devhelp> /help Где в проекте вызывается LLM API?
devhelp> /help На какой я ветке и что сейчас изменено?
devhelp> /exit
```

`/help` без вопроса показывает справку и примеры. Ctrl+D завершает диалог, Ctrl+C во время ответа отменяет его. Лог в том же терминале показывает выдачу поиска, подключение MCP, ветку, вызовы инструментов, раунды LLM, токены и стоимость. Под ответом код печатает использованные источники и предупреждает о неизвестных номерах или отсутствии ссылок.

Все команды принимают `--repo <корень git-репозитория>`, `index` и `help` — также `--db <индекс.sqlite3>`. По умолчанию репозиторий — родитель этого каталога, индекс — `data/docs_index.sqlite3`. Для собственных прогонов используйте свой `--db`; `DEVHELP_MODELS_DIR` задаёт отдельный кэш моделей. `DEVHELP_GIT_COMMAND` заменяет исполняемый файл MCP-сервера для проверки сбоев. Ключ LLM в окружение git-сервера не передаётся.

```bash
./week7/run.sh index --repo /путь/к/проекту --db /tmp/devhelp.sqlite3
./week7/run.sh help --repo /путь/к/проекту --db /tmp/devhelp.sqlite3 "Что делали в последних коммитах?"
./week7/run.sh git-server --repo /путь/к/проекту
```

Коды: `index` — 0 успех, 2 отказ до работы, 1 сбой, 130 прерывание; разовый `help` — 0 ответ, 1 сбой, 2 отказ старта, 130 прерывание. Чужой файл по `--db` не затирается; готовый индекс заменяется атомарно. Устаревшая документация и индекс другого репозитория вызывают предупреждение.

## Структура кода

| Файл | Назначение |
| --- | --- |
| `src/settings.py` | Пути, модели, параметры, промпты, цены, вопросы и замеры |
| `src/md_chunks.py` | Чистая нарезка Markdown с разделами и строками |
| `src/embedder.py` | Единственная граница `fastembed`: эмбеддинги и реранкер |
| `src/docs_index.py` | Сборка индекса SQLite и пробный поиск |
| `src/search.py` | Проверка индекса, ближайшие векторы и реранк |
| `src/llm.py` | Единственная граница `openai`: раунды и function calling |
| `src/mcp_client.py` | Клиент MCP v2, одно подключение на вопрос |
| `src/git_server.py` | Отдельный MCP-сервер, четыре инструмента чтения git |
| `src/devhelp.py` | Терминальный диалог, разовый вопрос, источники и лог |
| `run.sh` | `uv sync` и диспетчер команд |
