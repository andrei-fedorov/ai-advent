# Неделя 7 — продукты с LLM

Небольшие учебные продукты AI Advent Challenge живут здесь независимо от TooManyRules: своё окружение, зависимости и данные, проект передаётся через `--repo`.

## AI-ревью PR (день 32)

`review` получает изменения ветки и файлы через MCP, ищет связанную документацию и код (e5-base + реранкер bge), читает `AGENTS.md` из головы PR. Модель возвращает JSON; программа проверяет файлы, строки и ссылки на выдержки и собирает Markdown с разделами «Потенциальные баги», «Архитектурные проблемы», «Рекомендации». Проверки помечают несоответствия, решение по замечаниям принимает человек. Подробности — в [спецификации](docs/День%2032%20спецификация.md).

В GitHub Actions добавьте секрет `LLM_API_KEY`; необязательные переменные `LLM_BASE_URL`, `LLM_MODEL` выбирают OpenAI-совместимую модель. Первый push в `main` или ручной запуск workflow прогревает кэш моделей и индекса. Первая сборка на CPU может занять 25–40 минут (оценка); следующие пересчитывают только изменённые файлы. PR из этого репозитория получает один комментарий с меткой `<!-- week7-ai-review -->`, обновляемый при push, и сводку job. Черновики и форки пропускаются. Ревью не выставляет approve/request changes и не блокирует merge по замечаниям.

Пример формы ответа (не результат реального прогона):

```markdown
## 🤖 AI-ревью
PR меняет разбор ссылок.
### Потенциальные баги
1. **средняя** · `week7/src/devhelp.py:41` — Диапазон теряет верхнюю границу
   range(low, high) не включает high.
### Архитектурные проблемы
Не найдено.
### Рекомендации
Не найдено.
```

Лог показывает SHA ревизий, вызовы MCP и размеры ответов, отбор и обрезку файлов, отдельную выдачу документации и кода, раунды модели, токены и стоимость. В ревью сохраняются предупреждения индекса и ограничения контекста; слишком большие файлы модель дочитывает `git_show_file` по диапазонам строк.

## Запуск

Нужны Python 3.14 и `uv`. В `.env` этого каталога задайте `LLM_API_KEY`. Необязательные `LLM_BASE_URL` и `LLM_MODEL` меняют API; по умолчанию — `https://api.deepseek.com`, `deepseek-flash`. Заданное окружение имеет приоритет.

```bash
./week7/run.sh index
./week7/run.sh index --probe
./week7/run.sh review --base main
./week7/run.sh review --base origin/main --head HEAD --title 'Исправление' --out /tmp/review.md
./week7/run.sh help "Где в проекте вызывается LLM API?"
```

Локальное ревью сравнивает коммиты `base...head` от общего предка; незакоммиченные правки в него не входят. `--body-file` передаёт описание PR, `--link-base https://github.com/owner/repo/blob/SHA/` включает ссылки на строки. `--out` заменяется атомарно только после успешного ревью. Без него Markdown идёт в stdout после лога.

Корпус: `README.md`, `docs/*.md`, `week7/README.md` и код `src/*.py`, `week7/src/*.py`, `run.sh`, `week7/run.sh`. Шаблоны задаются в `settings.py`. Спецификации `week7/docs/` исключены: в них вопросы и ожидания; `AGENTS.md` и `CLAUDE.md` не индексируются. README и архитектура помечены текущим состоянием, исторические документы — днём. Схема SQLite дня 31 сохранена. `--full` пересчитывает всё; `--probe` отдельно показывает В1–В8 по документации и К1–К4 по коду. `help` по-прежнему ищет только документацию и даёт модели статус, лог и diff рабочего дерева.

Первый `index` скачивает около 1,6 ГиБ моделей в `data/models/`; `help` и `review` модели не скачивают. Все команды принимают `--repo`, все, кроме `git-server`, — также `--db`. По умолчанию проект — родитель `week7/`, индекс — `data/docs_index.sqlite3`. Для своих прогонов задавайте отдельный `--db` и `DEVHELP_MODELS_DIR`; `DEVHELP_GIT_COMMAND` заменяет исполняемый файл MCP для проверки сбоев. Ключ LLM серверу не передаётся.

```bash
./week7/run.sh index --repo /путь/к/проекту --db /tmp/review-index.sqlite3
./week7/run.sh review --repo /путь/к/проекту --db /tmp/review-index.sqlite3 --base main
./week7/run.sh git-server --repo /путь/к/проекту
```

Коды `review`: 0 — ревью, включая отсутствие изменений и сырой ответ вместо JSON; 2 — отказ старта; 1 — сбой API/MCP; 130 — прерывание. Прежний `--out` при сбое сохраняется. Чужой индекс не затирается; устаревший корпус и другая ревизия помечаются в логе и ревью.

## Структура кода

| Файл | Назначение |
| --- | --- |
| `src/settings.py` | Пути, модели, параметры, промпты, цены, вопросы и замеры |
| `src/md_chunks.py` | Чистая нарезка Markdown с разделами и строками |
| `src/code_chunks.py` | Нарезка кода блоками верхнего уровня |
| `src/embedder.py` | Единственная граница `fastembed`: эмбеддинги и реранкер |
| `src/docs_index.py` | Индекс SQLite документации и кода, пробный поиск |
| `src/search.py` | Проверка индекса, фильтры, ближайшие векторы и реранк |
| `src/llm.py` | Единственная граница `openai`: раунды и function calling |
| `src/mcp_client.py` | Клиент MCP v2, одно подключение на запуск |
| `src/git_server.py` | Отдельный MCP-сервер, семь инструментов чтения git |
| `src/devhelp.py` | Терминальный диалог, разовый вопрос, источники и лог |
| `src/review_report.py` | Номера строк, разбор JSON, проверки и Markdown |
| `src/pr_review.py` | Сбор контекста, RAG и ревью ветки |
| `run.sh` | `uv sync` и диспетчер команд |

Workflow проекта находится в корневом `.github/workflows/week7-review.yml`; Python-ревьюер от GitHub не зависит.
