# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Язык репозитория — русский: README, спецификации, промпты, строки интерфейса и комментарии в коде пишутся по-русски. Новые файлы следуют этому же правилу.

## Что это за репозиторий

TooManyRules — ассистент по правилам настолки Too Many Bones (Chip Theory Games), который пишется как проект для **AI Advent Challenge** (7 недель, задание каждый будний день). Приложение — Gradio-интерфейс поверх DeepSeek API (через SDK `openai` с `base_url` DeepSeek). RAG сознательно не делается до недели 5: модель отвечает из общих знаний, чтобы позже наглядно сравнить.

Продуктовая ценность вторична по отношению к учебной: каждый день — это демонстрация одного приёма работы с LLM, а не шаг к «лучшему ассистенту».

## Процесс: спецификация → промпт → исполнитель

Ключевая особенность проекта (см. §1 общей спецификации): **код пишется не Claude, а другими, более простыми AI-ассистентами.** Роль Claude здесь — планирование, спецификации по дням/неделям и ревью того, что сделал исполнитель. Отсюда цикл дня:

1. Организатор выдаёт задание → оно ложится в `tasks/` (локально, вне git).
2. Claude пишет `docs/TooManyRules — День N спецификация.md`.
3. Claude пишет `prompts/dayN-prompt.md` — роль-промпт исполнителю: что прочитать, в каком порядке работать, на что обратить внимание.
4. Исполнитель реализует; Claude ревьюит.
5. Коммит + тег `dayNN` (в таблицу челленджа идёт ссылка на тег, а не на `main`).

Прежде чем начинать писать код по запросу «сделай день N», уточни, нужна ли спецификация/промпт или реализация — по умолчанию в этом репозитории ожидается первое.

### Формат спецификации дня

Фиксированная структура, которую нужно сохранять у новых дней: задание челленджа → что делаем конкретно для TooManyRules → промпты/параметры → технические требования → что должно быть видно в видео → критерии приёмки → **«Что сознательно НЕ делаем на этом шаге»**. Последний раздел обязателен и обязателен к соблюдению исполнителем: он держит объём дня в рамках.

Текст самих заданий — платный контент челленджа. `tasks/`, `theory/` и `.claude/` в `.gitignore`; спецификации **ссылаются** на `tasks/AI Advent Challenge_0N.txt`, но не копируют его текст. Не переноси содержимое `tasks/` в коммитимые файлы.

## Команды

```bash
./run.sh
```

`run.sh` сам создаёт `src/.venv`, ставит `src/requirements.txt` и запускает `src/app.py` на http://127.0.0.1:7860 (Gradio-дефолт). Всё живёт в `src/`, не в корне: там же venv, `requirements.txt` и `.env` с `DEEPSEEK_API_KEY` (не коммитится). Python 3.14 (`src/.python-version`).

Вручную:

```bash
cd src && source .venv/bin/activate && python app.py
```

Тестов, линтера и сборки в проекте нет. Проверка изменений — ручная: запустить приложение, прогнать нужную вкладку и посмотреть stdout, куда логируется каждый вызов API (модель, `thinking`, `finish_reason`, время, токены, стоимость, текст ответа). Логи — основной инструмент отладки, добавляй их к новым вызовам тем же паттерном.

Для preview-сервера есть конфигурация `toomanyrules` в `.claude/launch.json` (порт 7860).

## Архитектура кода (текущее состояние — неделя 1, дни 1-5)

Весь код — один файл `src/app.py`: одно `gr.Blocks` с `gr.Tab` на каждый день. День N = вкладка + функция `run_dayN()` (день 1 — `respond`, день 2 — `compare_variants`). Дни 1-5 закончены и **не трогаются** при добавлении нового дня.

Что важно знать про этот файл:

- **`DEEPSEEK_EXTRA_BODY = {"thinking": {"type": "disabled"}}` передаётся во все вызовы дней 1-4 намеренно.** `deepseek-v4-flash`/`pro` — reasoning-модели с включённым по умолчанию thinking; скрытые reasoning-токены тратят тот же бюджет `max_tokens`, что и видимый ответ, из-за чего в дне 2 приходил пустой `content` и падал `json.loads`. День 5 — исключение: там режим thinking сам является переменной эксперимента и переключается через `extra_body`, а не именем модели.
- **Сравнивающие функции возвращают кортеж фиксированной длины**, который позиционно раскладывается в плоский список Gradio-выходов. Порядок — часть контракта: день 4 отдаёт 9 строк «по температурам, внутри по повторам» (0..2 → t=0.0, 3..5 → t=0.7, 6..8 → t=1.2), день 5 — 8 строк парами `metric_i, answer_i`.
- **`run_day5` намеренно не генератор.** Gradio показывает нормальный оверлей ожидания (спиннер + таймер) только для функций с одним `return`; у генератора вместо этого тонкая рамка без индикации.
- **Код нигде не оценивает качество ответов и не подсвечивает «лучший» вариант** — это ручное суждение автора по бумажной книге правил, явно исключённое из объёма в §7 каждой спецификации. Подсветка в дне 5 — только по объективным метрикам (время, `total_tokens`, стоимость), независимо по каждой.
- Стоимость считается по off-peak-таблице `PRICING_PER_M_TOKENS` ($ за 1M токенов); в пиковые часы ставки ×2, это осознанно оценка, а не выписка.
- Системные промпты выстроены наследованием от `SYSTEM_PROMPT` дня 1 (`SYSTEM_PROMPT_B`, `SYSTEM_PROMPT_STEP_BY_STEP`, `SYSTEM_PROMPT_CONSILIUM`) — базовая роль не меняется между днями.

## Перестройка на неделе 2 (день 6, спроектирован, ещё не реализован)

На границе недель кодовая база меняет форму — см. `docs/TooManyRules — Неделя 2 архитектура.md` и спецификацию дня 6:

- `src/app.py` → `src/app_week1.py`: замороженный артефакт недели 1, самодостаточный, вне графа импортов нового кода. Запуск через `./run.sh week1`. Его не рефакторят и из него не импортируют; дублирование промпта/констант/цен с новым кодом — осознанная цена заморозки.
- `src/agent.py` — сущность `Agent` + `AgentConfig` + `AgentReply`. **Единственное место в проекте, где вызывается LLM API.** Не знает ни про Gradio, ни про Too Many Bones.
- `src/presets.py` — конфиги агентов проекта (то, что на неделе 1 было разными кусками кода, становится разными `AgentConfig`).
- `src/storage.py` — появляется на дне 7 под уже объявленный в `agent.py` протокол `HistoryStore`.
- `src/app.py` — только Gradio: один экран без вкладок (чат + дебаг-панель), LLM-логики не содержит.

Направление зависимостей строго одностороннее: `app.py` → `presets.py` → `agent.py`, `app.py` → `storage.py` → `agent.py`. `agent.py` не импортирует ничего из проекта.

Дальше по неделе дни наращивают одну и ту же сущность (день 7 — история на диск, дни 8-10 — сжатие контекста и токены), поэтому вкладок больше нет, а «что нового сегодня» показывает растущая дебаг-панель. Абстракции под будущие дни заранее не пишутся — фиксируются только места, куда они встанут.
